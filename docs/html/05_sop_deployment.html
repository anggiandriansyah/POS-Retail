1. Latar Belakang & Tujuan Kebijakan

Dokumen ini menetapkan Standar Operasional Prosedur (SOP) resmi yang mengikat bagi seluruh tim pengembang perangkat lunak pada proyek POS Toko Retail. Tujuan utama SOP ini adalah memastikan setiap pembaruan sistem yang didistribusikan ke lingkungan pengujian (DEV) maupun produksi (PRODUCTION) memiliki rekam jejak tertulis yang lengkap, transparan, terverifikasi, dan mudah dipahami oleh pemilik bisnis, kasir, dan tim audit teknis.

KETETAPAN KESEPAKATAN (MANDATORY RELEASE RULE):
"Setiap kali proses deployment selesai dilakukan (pada rilis Sprint berjalan maupun sprint-sprint selanjutnya), Technical Writer (TW) MEMILIKI KEWAJIBAN MUTLAK untuk menerbitkan dan memperbarui 4 paket dokumen resmi dalam format PDF siap cetak / siap edar sebelum siklus rilis dinyatakan resmi ditutup (Definition of Done)."

3. Alur Kerja Paska-Deployment (Workflow Steps)

Setiap anggota tim wajib mematuhi alur kerja paska-deployment berikut secara berurutan:

1
Deployment Selesai & Terverifikasi (DevOps / Lead Dev):
DevOps memastikan migrasi database berhasil dieksekusi di Supabase dan deployment branch main berstatus Ready (HTTP 200) di Vercel. Kredensial, commit SHA, dan log hasil pengujian diserahkan ke Technical Writer.
2
Penyusunan Konten Dokumen (Technical Writer):
TW memeriksa source code terbaru, migrasi SQL, hasil test suite, dan antarmuka UI aktual untuk memastikan seluruh penjelasan fitur akurat dan tidak ada fitur fiktif.
3
Kompilasi ke Format PDF Vektor (Technical Writer):
TW mengompilasi dokumen menggunakan stylesheet cetak A4 profesional, memastikan tabel tidak terpotong (page-break-inside: avoid), tipografi tajam, dan menyimpannya di folder docs/pdf/.
4
Pembaruan Indeks Katalog (Technical Writer):
TW memperbarui file docs/README.md dan README.md utama proyek agar selalu menautkan ke file PDF versi terbaru.
5
Sinkronisasi Repositori Git (DevOps / TW):
Seluruh file PDF dan dokumentasi markdown di-commit dan di-push ke branch develop dan main pada repositori GitHub.
6
Penyerahan Laporan Resmi ke Product Owner:
Ringkasan hasil rilis beserta tautan langsung ke dokumen PDF disampaikan kepada Pemilik Toko / Product Owner untuk mendapatkan persetujuan akhir.

4. Ketentuan Mutu Format Dokumen PDF

Standar Desain & Keamanan PDF:
1. Ukuran Standar: Kertas A4 dengan margin 16mm, ramah cetak (printer-friendly) dan nyaman dibaca di layar tablet/HP.
2. Keamanan Data: DILARANG KERAS mencantumkan secret token, API key privat, atau password database di dalam dokumen.
3. Vektor & Tipografi: Menggunakan font sistem modern (San-Serif clean) agar teks tetap tajam saat di-zoom dan dapat di-copy paste secara presisi.
4. Integritas Penamaan: Penamaan file PDF wajib menggunakan awalan angka urut (01_... s.d. 05_...) agar tersusun rapi saat diunduh.
